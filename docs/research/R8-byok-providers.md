Researched 2026-10-30. Sources: live `curl` probes of each endpoint (no key), official docs where fetched, and the installed pi-ai catalog at `harness/packages/llm/llm-pi-ai/node_modules/@earendil-works/pi-ai/dist/providers/data/*.json` plus `harness/packages/llm/llm-pi-ai/src/provider-data.generated.ts`.

## How to read this

- **id**: the pi-ai catalog id where one exists. Ids marked `custom` are not in the installed catalog and need a hand-declared route (`api`, `baseURL`, `models`) per the adapter README.
- **api**: the adapter supports only `openai-completions`, `openai-responses`, and `anthropic-messages` (`src/provider.ts`). The pi-ai catalog uses `google-generative-ai` for `google` and `mistral-conversations` for `mistral`. The adapter cannot dispatch either, so those two routes need `api: openai-completions` and the compat `baseURL` set explicitly.
- **Probe**: the HTTP status of `GET modelsUrl` without a key. A 401 or 403 means the endpoint exists and wants auth. A 200 means the list is public.
- **Caps**: whether the models list returns context length and tool support. "Unverified" means it needs a key to check.
- Anything not confirmed by a probe or a fetched doc is marked UNVERIFIED.

## Special headers

- **Anthropic**: `x-api-key: <key>` plus `anthropic-version: 2023-06-01`. The models list is `GET /v1/models?limit=1000`, which matches the adapter README.
- **OpenRouter**: `Authorization: Bearer <key>`, plus the optional attribution headers `HTTP-Referer: <app url>` and `X-Title: GhostCode`.
- **Google Gemini (compat)**: `Authorization: Bearer <key>`. Without a key, the compat `/models` endpoint returns 404. With a bad bearer token it returns 400 "Please pass a valid API key", which confirms the route exists.
- **All others**: `Authorization: Bearer <key>`.
